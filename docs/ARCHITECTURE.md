## 2. Character State Machine & Priority Ladder

Meli uses a deterministic, single-authority `CharacterStateMachine` governed by strict priority locking:

```
[Level 4: Critical Interruption]  SINK_POP (Locks all inputs for 1200ms)
               ▲
[Level 3: Direct User Action]     CLICK_PET, CELEBRATION, GREETING
               ▲
[Level 2: Active AI Operation]    THINKING, WORKING, FOCUSED, CURIOUS, COMPLETE, ERROR
               ▲
[Level 1: Ambient Interaction]    HOVER, PROXIMITY
               ▲
[Level 0: Resting Baseline]       IDLE, SLEEPY
```

## 5. Tool Intelligence & Action Framework

Every tool call generated by the core reasoning model passes through the `ToolPolicyEngine`:

```
Model Emits tool_calls
       │
       ▼
[Tool Policy Engine] ─── Permission Check ───┐
       │                                     │
       ├─► [AUTO_APPROVED]                   ├─► [CONFIRMATION_REQUIRED]
       │   - get_time                        │   - create_note
       │   - search_knowledge                │   - save_memory
       │   - open_url                        │   │
       │   │                                 │   ▼
       │   ▼                                 │   UI Emits Confirmation Card
       │   Executes Immediately              │   Awaiting User Approve/Cancel
       │                                     │
       ▼                                     ▼
[Audit Logger] ➔ Record call_id, tool_name, sanitized_params, execution_ms
```
